# Rôle

Tu es un développeur C# senior, expert en WPF (.NET 8), MVVM et applications desktop de bureau. Tu produis du code propre, testable et documenté.

# Mission

Concevoir et implémenter une application WPF complète nommée **TextAnonymizer** : un anonymiseur de texte réversible, avec table de conversion, génération automatique de valeurs fictives et surlignage visuel des remplacements.

# Contexte fonctionnel

L'utilisateur colle un texte brut, l'application le transforme selon une **table de conversion** (mots exacts), et produit un texte anonymisé. L'opération inverse (rétablissement) doit être réalisable. Le mapping est bijectif : un mot original correspond à un et un seul remplaçant, et réciproquement.

# Exigences fonctionnelles

## 1. Détection / matching
- Remplacement basé sur une **table de mots exacts**.
- Stratégie de matching **configurable par table** :
  - `Strict` (respect casse et accents),
  - `IgnoreCase` (insensible à la casse),
  - `IgnoreCaseAndDiacritics` (insensible casse + accents).
- En cas de chevauchement entre règles, la correspondance **la plus longue** gagne.

## 2. Table de conversion
- Format **JSON**, persistée localement avec **chiffrement automatique** (AES ; clé protégée via DPAPI / `System.Security.Cryptography.ProtectedData`).
- Chaque entrée contient au minimum : mot original, remplaçant, type d'entité (ex: `Nom`, `Ville`, `Email`, `Tel`, `Autre`), statut (manuel / auto-généré).
- **Validation de la bijection** : rejeter tout doublon côté original ou côté remplaçant, avec message d'erreur explicite.
- Opérations CRUD complètes sur la table (ajouter, éditer, supprimer, importer, exporter).

## 3. Génération automatique (option activable)
- Pour chaque entrée **étiquetée par l'utilisateur** (colonne type), générer une **valeur fictive réaliste** en français :
  - `Nom` → prénom + nom français plausibles (ex: « Martin Dubois »),
  - `Ville` → ville française réelle,
  - `Email` → email plausible cohérent avec le nom généré,
  - `Tel` → numéro au format français valide,
  - `Autre` → pseudonyme générique (`ELEMENT_1`, `ELEMENT_2`…).
- Les valeurs générées doivent être **uniques** dans la table (bijection préservée).
- L'utilisateur voit un **aperçu des remplacements proposés avant application**, puis valide.

## 4. Réversibilité
- Bouton `Anonymiser` (source → résultat) et bouton `Rétablir` (résultat → source, en inversant le mapping).
- La table étant la clé de réversibilité, afficher un avertissement si l'utilisateur tente de la modifier après une anonymisation (perte de réversibilité possible).

## 5. Interface utilisateur — trois zones
1. **Source** : texte brut entrant (coller / bouton coller).
2. **Résultat** : texte anonymisé (bouton copier).
3. **Table de conversion** : grille éditable des entrées.
- **Surlignage visuel** des segments remplacés dans le texte résultat : utiliser `RichTextBox` + `FlowDocument`, fond coloré par type d'entité, tooltip affichant la valeur d'origine au survol.
- Barre d'outils : `Anonymiser`, `Rétablir`, `Générer automatiquement`, `Aperçu`, `Charger/Enregistrer la table`.
- Copier/coller via boutons dédiés utilisant `Clipboard.SetText` (texte brut, jamais du XAML).

## 6. Aperçu avant application
- Liste des remplacements proposés (original → remplaçant, type), modifiable ligne par ligne, puis validation globale ou rejet.

# Architecture imposée (MVVM)

```
TextAnonymizer/
├── Models/
│   ├── ConversionEntry.cs      // Original, Replacement, EntityType, IsAutoGenerated
│   ├── ConversionTable.cs      // Entries, MatchingStrategy, ValidateBijection()
│   ├── EntityType.cs           // enum : Nom, Ville, Email, Tel, Autre
│   ├── MatchingStrategy.cs     // enum : Strict, IgnoreCase, IgnoreCaseAndDiacritics
│   └── ReplacementResult.cs    // Texte transformé + liste de segments (index, longueur, entrée)
├── Services/
│   ├── IConversionService.cs   // Anonymize(), Restore(), retourne ReplacementResult
│   ├── ConversionService.cs    // Matching selon stratégie, priorité longueur
│   ├── IGeneratorService.cs    // Generate(EntityType, existing) : valeur fictive réaliste
│   ├── GeneratorService.cs    // Listes internes de prénoms/noms/villes français
│   ├── ITableStorageService.cs // Load/Save chiffrement AES + DPAPI
│   ├── TableStorageService.cs
│   └── ClipboardService.cs     // SetText/GetText texte brut
├── ViewModels/
│   ├── MainViewModel.cs        // Orchestration des 3 zones, commandes
│   ├── TableViewModel.cs       // CRUD, validation, aperçu
│   └── PreviewViewModel.cs     // Liste modifiable des remplacements proposés
├── Views/
│   ├── MainWindow.xaml         // Layout 3 zones
│   ├── SourceView.xaml
│   ├── ResultView.xaml
│   └── TableView.xaml
└── Converters/                 // BoolToVisibility, etc.
```

# Exigences techniques

- **.NET 8**, WPF, C# 12.
- MVVM strict : `CommunityToolkit.Mvvm` autorisé (`ObservableObject`, `RelayCommand`).
- `ConversionService` retourne **à la fois** le texte transformé **et** la liste des segments trouvés (index, longueur, entrée) — le ViewModel s'en sert pour appliquer le surlignage via `TextRange` dans le `FlowDocument`.
- Aucune logique métier dans le code-behind des vues.
- Services injectables (constructeur ou DI simple), interfaces pour chaque service.
- Gestion des erreurs : messages utilisateur clairs (table invalide, doublons, texte absent).

# Tests

- Tests unitaires (xUnit) pour : `ConversionService` (matching selon chaque stratégie, priorité longueur, réversion exacte), `GeneratorService` (unicité, cohérence type/valeur), validation de bijection.

# Critères d'acceptation

1. Coller un texte dans Source, cliquer Anonymiser → Résultat affiche le texte anonymisé avec segments surlignés et tooltips.
2. Cliquer Rétablir → le texte original est restauré à l'identique (vérification string equality).
3. Une table avec doublons est rejetée avec un message explicite.
4. La génération auto produit des valeurs réalistes par type, uniques, après validation de l'aperçu.
5. La table sauvegardée est illisible en clair sur disque (chiffrée).
6. Les boutons Copier/Coller transfèrent du texte brut uniquement.
7. `dotnet build` sans avertissement, tous les tests verts.
